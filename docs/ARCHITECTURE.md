# Architecture

## Static site

Mack Richardson's personal website publishes a blog and standalone pages. Astro 7 builds static HTML and assets using [the Astro configuration](../astro.config.mjs). Astro Icon and sitemap are integrations, RSS is generated by a route, and the image pipeline uses Astro's Sharp service. There is no application database, runtime API backend, or account system in the checkout.

| Location | Responsibility |
| --- | --- |
| [src/pages](../src/pages) | Home, paginated journal, articles, taxonomy, About, Privacy, 404, RSS, and the standalone Holiday Cards archive |
| [Layout.astro](../src/layouts/Layout.astro) | Shared document metadata, desktop and Newton shells, page slot, static About/category/privacy popups, and window manager |
| [src/components](../src/components) | Site chrome, navigation, windows, content presentation, and client scripts |
| [src/content/blog](../src/content/blog) and [content.config.ts](../src/content.config.ts) | Markdown posts and the Astro Content Layer schema |
| [site.json](../src/data/site.json) and [utils.js](../src/js/utils.js) | Site metadata, URL slugging, date formatting, and publication filtering |
| [style.css](../style.css), [src/css](../src/css), and [Newton CSS](../src/css/newton/index.css) | Global reset, fonts, variables, defaults, components, utilities, and notebook-specific overrides |
| [src/assets/blog](../src/assets/blog) and [public](../public) | Optimized article hero inputs and directly served assets such as article body images and local fonts |

## Content flow

The blog collection loads Markdown with a glob. Its schema requires title, date, author, hero image and alt text, description of at most 160 characters, and an enumerated category. It supports an optional hero class and tags, with `draft` and `mackdaddy` defaulting to false. Routes use the collection entry ID and the shared slugging helper. Article bodies use Astro's `render(post)`. Default publication filtering excludes drafts and future posts and sorts newest first. The [RSS route](../src/pages/rss.xml.js) uses the same filter and article URL convention.

Hero images are referenced relative to the post and processed by Astro. Body images served from `public/assets/` use root-relative URLs and bypass that pipeline. The tag route assumes every published entry has a tags array, although the schema allows omission. See [CURRENT-STATE.md](CURRENT-STATE.md).

## Browser interaction

- **Up to 1024px**, [NewtonShell.astro](../src/components/NewtonShell.astro) presents a notebook with normal page navigation and scrolling. Extras uses a native modal dialog and links to the standalone Privacy page.
- **Above 1024px**, [WindowManager.astro](../src/components/WindowManager.astro) manages draggable desktop windows. It fetches supported internal pages, extracts their window content, and waits for linked production stylesheets before opening the window. Failed loads fall back to page navigation. Resizing across the breakpoint restores the current page content to the appropriate layout.
- [Holiday Cards](../src/pages/holiday-cards/index.html) is independent HTML with its own Christmas theme and lightbox.

The window loader inserts fetched site markup into the DOM. Preserve the trusted site-content boundary when editing it. [BaseHead.astro](../src/components/BaseHead.astro) loads the remote Font Awesome kit used by Newton's decorative pixel icons. [GoogleAnalytics.astro](../src/components/GoogleAnalytics.astro) integrates Google Analytics, which the shared [privacy content](../src/components/Popup-Privacy.astro) discloses.

## Build and hosting

[package.json](../package.json) defines the Node-based workflow. The build runs Astro checks, emits `dist/`, builds a Pagefind index there, and copies that index into `public/`. Pagefind has no wired search interface. CSS minification targets are pinned in Astro config to avoid emitting syntax older Safari cannot parse. Production preview matters because fetched-page styles may be linked CSS in production and inline during development.

[README.md](../README.md) identifies GitHub `main` as the Netlify production branch. Hosting dashboard settings and current deployment health require separate verification. The checkout has no dedicated test or lint script and no GitHub Actions workflows. See the [November 2 QA record](qa-2026-11-02.md) for the manual production-build checks.
