# Newton and desktop follow-up review — November 2, 2026

Scope: TODO #32–#34. Tested the local **production build** served at
`http://127.0.0.1:4327`, with the Codex in-app browser. This is a targeted
regression/accessibility review, not a WCAG conformance certification.

## #32 — physical devices and responsive behavior

Mack reports testing on **iPhone and Android with no UI problems encountered**.
He also reports that iPad displays Mac OS 9 and accepts this behavior. Theme
selection uses viewport width, not device detection: up to and including
1024px uses Newton; larger widths use Mac OS 9. An iPad can therefore change
themes with orientation, split view, or window size.

Browser checks on the Doctor Who article at viewport widths 320, 390, 844,
1024, 1025, and 1280px found no horizontal document overflow. Repeated
transitions across 1024px preserved exactly one article heading and restored
normal document content on the Newton side. Mobile Journal navigation and
browser Back/Forward worked.

Still unconfirmed on physical hardware: detailed safe-area/browser chrome
changes, long-page scroll and history restoration, and rotation across the
breakpoint. Mack's general feedback does not establish each scenario separately.

## #33 — accessibility

Corrected findings:

- Desktop dropdowns now have named disclosure buttons with `aria-expanded`
  and `aria-controls`. Enter/Space toggle, ArrowDown opens and focuses the
  first link, and Escape closes and returns focus to the trigger. Hover still
  opens dropdowns and the parent stays highlighted while a child has focus.
- Closed static popups, fetched windows, and the closed homepage card become
  inert and hidden from assistive technology. Reopening restores accessibility;
  resizing to Newton restores a previously closed homepage card. Desktop window
  close controls have explicit labels; windows have dialog names. Closing a
  focused window attempts to restore its opener.
- Article tag links are available to keyboard and assistive technology, with
  visible focus outlines. Their previous `aria-hidden`/negative tabindex were
  inappropriate for navigation links.
- Extras explicitly wraps Tab/Shift+Tab between its controls. The browser's
  native dialog allowed reverse Tab to move focus out of the page in this test;
  the explicit wrap resolved it. Verified both boundaries and Escape returning
  focus to Extras. Native modal behavior hides background content from the
  accessibility tree.
- Desktop red/pink tag backgrounds are lighter for dark text. Calculated tag
  foreground/background contrast across all five colors is 4.79–7.23:1.
  Newton ink/base contrast is 10.13:1; secondary ink/base is 5.04:1.
  Footnotes now use opaque ink rather than low-contrast half-opacity text.
- Shared header/popups/scripts now sit inside the authored HTML body, avoiding
  reliance on browser repair of the document structure.

Verified dropdown expansion/focus/Escape, popup keyboard closing, exclusion of
closed windows from the accessibility tree, named mobile controls, and Journal
`aria-current` indication. Reviewed CSS target dimensions (toolbar 60px,
Extras close 44px, shortcut/folder controls at least 48px, mobile tags 36px).

Remaining manual checks: actual VoiceOver/TalkBack reading order and output,
200% text-only zoom, and a complete per-control touch-target measurement.
Accessibility-tree inspection is not a substitute for a screen-reader session.
Contrast figures cover the listed theme colors, not every image or state.

## #34 — desktop regression pass

Passed:

- Production homepage fresh load and direct article load.
- Blog and Doctor Who article fetched as separate desktop windows. The linked
  production article stylesheet is imported by the loader before opening;
  article content, tags, and share controls appear in the accessibility tree.
- Closed article disappears from the accessibility tree; underlying navigation
  remains usable.
- Privacy popup opens from Help and closes with mouse and keyboard activation.
- About page opens as a fetched window from the homepage button.
- Dropdown parent uses the blue selection background while a child has focus;
  Escape collapses the disclosure.
- Homepage button center differs from its container center by less than 0.01px.
- Homepage window drag moved it 100px horizontally and 60px vertically.
- Repeated desktop/Newton transitions preserve the article without duplicate
  content or horizontal overflow.

Validation: `npm run build` passed (Astro check, static output, Pagefind), and
`git diff --check` passed. Mack subsequently approved committing and pushing
the review fixes to `main`.
